## 0. 요약

1. **"constraints가 너무 많다"는 보상 관점에서는 대부분 표면적인 문제다.** compliance는 항목 평균이 아니라 **신호 평균**이다. 신호는 단계마다 하나, 그리고 순서와 전역 규칙이다. 그래서 항목 수와 보상 비중이 다르다.
   - 산출물 형식(S10)은 항목 수로는 61~73%이지만, 점수 몫으로는 20~38%다.
   - 순서 항목은 workflow당 1~3개뿐이지만 점수의 17~23%를 차지한다.
   - 채점되지 않는 `unimplemented`가 학습 rubric 항목의 24%다.
2. **결정된 제외(AOS `blocks` 2개, SKB 파일 목록 `cross_ref` 3개)는 보상 분포를 거의 바꾸지 않는다.** 이 제외는 L2 확보를 위한 것이고, 보상 균형을 위한 조정이 아니다.
3. **보상 분포를 실제로 바꾸는 선택지는 두 가지다.**
   - **A:** 보상 결합 방식을 `mul`에서 `add`로 바꾼다. rubric 밖의 설정이지만 영향이 가장 크다.
   - **B:** 형식 계열 content 항목을 단계 승수로 옮긴다. 결정이 필요하다(4절).
4. **unimplemented 187개 정리:** 대부분 SDLC 절차와 무관하거나 중복이라 삭제를 제안한다. 구현할 가치가 있는 12개는 Future work ① 후보로 둔다(6절).
5. **문서 검토로 3단계 판정 두 건을 정정했다(7절).** 이전 산출물 재작성 금지(G8)는 openspec_ff 기준으로 충돌이다. 산출물 재독 금지(T-RD6)는 agentos_v2에 부분 노출이 있다.

## 1. 보상이 계산되는 방식

| 단계 | 계산 | 근거 |
|---|---|---|
| 항목 | 0~1 점수, 가중치 must 1.0 / should 0.25 | `aggregate.py` |
| 단계 점수 | (골격 항목의 가중 통과율) × (content·evidence 항목의 가중 통과율). 게이트 실패 시 0 또는 상한 0.1 | `sigma_kappa` |
| 신호 | 단계마다 하나 + `order`(전역 순서 항목) + `process`(그 밖의 전역 항목 × 단계 점수 평균) | `aggregate.score` |
| compliance | 신호들의 단순 평균 | `compliance: mean` |
| 학습 보상 | `mul`: 정답 여부(0/1) × compliance / `add`: 정답 여부 + λ × compliance (λ 기본 0.2) | `train.py` |

**함의:**
- 신호가 6~7개라 **단계 하나가 보상의 1/6~1/7을 차지한다.** 그 단계 안의 항목이 몇 개든 몫은 같다.
- 골격 항목은 **점수를 주지 않고 곱하기만 한다.** 제목이 하나 빠지면 그 단계의 행동 점수까지 깎인다.
- 라운드 항목(SKB fix_2 ~ test_3)은 그 라운드 산출물이 있을 때만 판정된다(`applies_when`). 보통 실행에서는 보상에 들어가지 않는다.
- 게이트(AOS 15, OSF 18, SKB 9)는 빈 산출물이나 자리표시자만 쓴 산출물로 점수를 얻는 것을 막는다. **정리 대상에서 제외하고 유지한다.**

**이전 실험의 근거:** AI-DLC × SWE-Gym 학습 보고서(2026-09-30) 기준이다.
- 원본 모델의 compliance는 평균 0.02였고, 90.7%가 정확히 0이었다. 원인은 항목 세부가 아니라 **workflow 진입 실패**였다. core 문서를 읽은 비율이 13.8%였다.
- 진입하고 산출물을 쓴 경우 골격 품질은 높았다. Stage 1 만점이 58개 중 54개였다.
- `mul`에서는 4-rollout 그룹의 74%가 advantage 0(학습 신호 없음)이었다. `add`(λ 0.2)에서는 38%였다.

→ **rubric을 줄이는 것보다, 모델이 workflow에 들어가 단계를 진행하는지에 보상이 반응하게 하는 것이 먼저다.**

## 4. 보상 분포를 바꾸는 선택지 (결정 필요)

### A. 보상 결합: `mul` → `add` (rubric 밖, 권장)

- **근거:** 이전 실험 보고서 4절. `mul`이면 정답이지만 workflow를 따르지 않은 rollout이 오답과 같은 0을 받습니다. 그룹의 74%가 학습 신호를 잃었습니다.
- **제안:** `recipe.workflow.compliance_reward.mode=add`, λ 0.2~0.5로 시작합니다. compliance > 0 비율이 충분히 오르면 `mul`을 검토합니다. `mul`을 유지한다면 floor(예: 0.2 + 0.8·c)를 둡니다.
- 학습 workflow 세 개의 원본 모델 compliance 분포는 아직 측정되지 않았습니다. 같은 진입 문제가 있는지 첫 실행에서 확인해야 합니다.

### B. 형식 계열 content 항목을 단계 승수로 이동 (rubric 변경, 선택)

- **내용:** 필드 채움·허용값·반복 항목 형식(S10) 중 `class: content`인 항목을 `structure`로 바꿉니다. 형식은 "갖춰야 할 조건"(승수)이 되고, 점수는 행동·사실성 항목에서 나옵니다.
- **효과 (`--after --fmt-to-struct`):**

  | 기술 | AOS | OSF | SKB |
  |---|---|---|---|
  | S1 문서 따르기 | 35.8% | 17.8% | 16.9% |
  | S2 단계 순서 | 16.7% | 17.1% | 23.3% |
  | S3 행동 허용 구간 | 17.1% | 40.3% | 19.1% |
  | S4 금지 대상 | 5.1% | 8.2% | 13.3% |
  | S5 산출물 쓰기 규율 | 12.6% | 9.0% | 13.4% |
  | S6 기록의 사실성 | 5.9% | 0.6% | 14.0% |
  | S7 진행 기록 | 2.2% | 3.9% | |
  | S9 질문 대신 스스로 결정 | 1.9% | 2.6% | |
  | S10 산출물 형식 | 2.7% | 0.5% | |

- **확인한 것:** 바꾼 뒤에도 모든 단계에 행동 계열 점수 항목이 3개 이상 남습니다. 점수 항목이 하나도 없는 단계는 엔진이 승수만으로 점수를 내서 형식이 단계 점수 전체가 되는데, 그런 단계는 생기지 않습니다.
- **장점:** 이전 실험에서 산출물을 쓰면 형식은 대부분 맞았습니다(분산이 작음). 그래서 학습 신호가 행동 항목에 집중됩니다.
- **단점:**
  - "내용을 채워 썼다"는 것 자체로는 점수가 나오지 않습니다. 예를 들어 요구사항 문서를 성실히 쓰는 것이 승수 조건이 됩니다.
  - 필드 하나가 빠지면 그 단계의 행동 점수 전체가 줄어듭니다. 형식 오류의 벌점이 커집니다.
  - 항목 class를 바꾸는 것이라 생성기 규칙(`classify`)이나 manual 항목 수정이 필요합니다.
- **판단 기준 (2026-10-23 정정):** 형식 항목이 거의 항상 통과할수록 B가 유리하다.
  - **형식이 항상 통과하는 경우:** 지금처럼 κ(점수 쪽)에 있으면 고정 점수를 깔아 행동 점수의 변화폭을 줄인다. 예를 들어 형식 6개가 항상 통과하고 행동 4개가 0→4로 바뀌어도 κ는 0.6→1.0으로 0.4만 변한다. 보상은 정답 여부와 합쳐지므로, 이 희석은 절차 준수 신호의 상대적 크기를 줄인다. B로 옮기면 σ ≈ 1이라 비용이 거의 없고, 희석이 사라진다.
  - **형식이 자주 실패하는 경우:** B에서는 필드 하나가 그 단계의 행동 점수 전체를 깎는 강한 벌점이 된다.
- **권장:** A를 적용한 첫 학습 또는 원본 모델 측정에서 형식 항목의 통과율을 확인한다. **거의 항상 통과하면 B를 적용**하고, 실패가 잦으면 해당 형식 항목부터 점검한다.
