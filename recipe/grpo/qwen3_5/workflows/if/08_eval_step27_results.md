## 0. 요약

- **문제 해결률은 같다.** base 0.515, step27 0.519. 같은 task 쌍으로 보면 step27이 새로 푼 46개와 놓친 44개가 상쇄된다.
- **지시 따르기(compliance)는 크게 오른다.** 0.343 → 0.783. 네 평가 층 중 셋(L1, L2-중간, L2-먼)이 +0.38~+0.42, 충돌 층은 +0.11.
- **오른 이유의 절반은 "끝까지 간다"이고 절반은 "간 뒤에 더 잘 지킨다"다.** 산출물 5개를 모두 쓴 run이 51% → 93%. 두 모델 모두 완주한 같은 task만 비교해도 compliance가 +0.24 차이난다.
- **해결 여부·base의 사전 compliance와 무관하게 비슷한 폭으로 오른다.** 못 푼 task에서도, base가 절차에 전혀 들어가지 못한 task에서도 step27의 compliance는 0.75~0.81이다.
- **학습 workflow와 충돌하는 지시(L1-충돌)에서 악화 신호는 없다.** 다만 이 층은 두 모델 모두 불안정하다(재독 금지 0.59 → 0.59, 지연 실행 0.55 → 0.66).
- **step27이 여전히 못 지키는 것:** 기록과 실제 실행의 일치(0.35), 수정 전 baseline 실행(0.42), 같은 범위로 재실행(0.39), 뒷단계 문서 미리 읽지 않기(0.57). 산출물의 *형식*은 거의 다 지키지만 *행동*과 *사실성*은 절반 수준이다.

## 1. 배경 개념 (if 폴더 문서를 안 읽은 사람을 위해)

### 1.1 무엇을 학습했고 무엇으로 평가하나

모델은 Qwen3.5-9B다. **학습**은 세 개의 SDLC workflow(`agentos_v2`, `openspec_ff`, `speckit_bug`)를 따라 SWE-Gym 문제를 풀게 하고, 문제 해결 + workflow 지시 준수로 보상을 주는 GRPO다. **평가**는 학습에 쓰지 않은 네 번째 workflow **AI-DLC v4**로 SWE-bench Verified 499문제를 풀게 하는 것이다. 즉 "학습 workflow에서 배운 '지시 따르기'가 처음 보는 workflow로 옮겨가는가"를 묻는다.

AI-DLC v4는 다섯 단계이고 단계마다 정해진 경로에 산출물 문서를 하나씩 쓴다(a1 reverse engineering → a2 requirements → a3 design → a4 plan → a5 report). 이 문서에서 **"완주"**는 다섯 산출물을 모두 쓴 run, **"진입"**은 하나 이상 쓴 run이다.

### 1.2 compliance는 어떻게 계산하나

workflow 문서에서 뽑은 **지시 항목(rubric item)** 하나하나를 코드로 판정한다. 예: "a1 문서에 `## Baseline` 절이 있다", "첫 소스 수정 전에 테스트를 한 번 실행했다", "a5의 변경 파일 목록이 실제 diff와 같다". 항목은 `must`(점수에 반영)와 `should`(진단용)로 나뉜다. AI-DLC 평가 rubric의 must 항목은 191개다. **compliance**는 이 항목들의 통과 여부를 단계별로 모아 0~1로 만든 값이다.

같은 판정 로직을 쓰는 항목들을 **템플릿(T-\*)** 으로 묶고, 템플릿을 열 가지 **기술(S1~S10)** 로 분류했다(01 문서). 이 문서에 나오는 템플릿:

| 템플릿 | 기술 | 뜻 |
|---|---|---|
| T-FM1/2/3/4/5/6 | S10 산출물 형식 | 파일 존재, 절·라벨·필드 존재, 번호 매기기, placeholder 잔여 없음, frontmatter 키, 반복 블록의 필드 |
| T-RD1, T-RD3, T-RD4 | S1 문서 따르기 | 핵심 문서 먼저 읽기, 뒷단계 문서 미리 안 읽기, 앞단계 산출물을 정해진 구간에 읽기 |
| T-RD6 | S1 | 아직 보이는 자기 산출물을 다시 읽지 않기 |
| T-OR1, T-OR3 | S2 단계 순서 | 읽기·쓰기 순서 사슬, 앞단계로 되돌아가지 않기 |
| T-AW1~T-AW6 | S3 행동 구간 | 허용 단계 밖 수정 금지, 수정 전 baseline 실행, 마지막 수정 후 테스트, 지연 실행, 같은 범위 재실행 |

| T-SR2 | S9 스스로 결정 | 사용자에게 질문하지 않기 |

### 1.3 평가 층(layer)이란

평가 항목을 **학습 때 비슷한 것을 본 정도**로 네 층으로 나눈 것이다(02·03 문서). 층은 평가 workflow의 항목마다 붙는 라벨이고, 학습 workflow에는 없다.

| 층 | 뜻 | must 항목 수 | 보는 것 |
|---|---|---|---|
| **L1** (seen) | 학습 workflow에서 보상받은 템플릿의 지시를 처음 보는 workflow 문서에 적용 | 167 | 배운 것을 새 문서에서도 지키는가 (cross-workflow 전이) |
| **L1-충돌** (L1C) | 학습 workflow의 규칙·문서와 *반대 방향*인 지시 | 5 | 학습 습관이 아니라 현재 문서를 따르는가. 학습 후 떨어지면 과적합 신호 |
| **L2-중간** (L2M) | 학습 보상에는 없지만, 학습 템플릿의 구조를 확장했거나(구조 확장형: T-TR2, T-RF3) 학습 workflow 문서에 지시가 노출된(문서 노출형: T-SR2, T-AW6) 템플릿 | 13 | 가까운 일반화. 문서 노출형은 seen에 가까우므로 L2-먼과 따로 본다 |
| **L2-먼** (L2F) | 학습 rubric과 문서 어디에도 없는 템플릿 (순수 unseen: T-FM5, T-TR1b) | 6 | 먼 일반화 |

층 점수는 그 층의 must 항목 통과율(0~1)이다. 두 가지로 센다.

- **전체 run 기준** (`layer/L`): 모든 run을 센다. 산출물을 안 써서 항목이 판정 불가면 실패로 친다. "결과적으로 얼마나 지켰나".
- **도달 기준** (`layer_reached/L`, 표에서 `r` 접두어): 해당 단계에 실제로 들어간 run만 센다. "그 단계에 왔을 때 지켰나". 완주율 차이를 걷어낸 비교다.

### 1.4 채점 방법과 신뢰도

평가 에피소드에는 모델의 전체 대화 기록과, 실행 종료 시점에 수집한 **실제 산출물 파일**과 **repo diff**가 저장되어 있다. 이 둘을 그대로 써서 191개 항목을 다시 판정했으므로 학습 중 실시간 채점과 거의 같은 조건이다(판정 불가 항목 0). 표의 `live v4`는 원래 `aidlc_v4` 채점기가 평가 당시 매긴 compliance이고, `ifeval`은 이 문서의 새 기준으로 다시 매긴 값이다. 두 값의 경향은 같고 절대값만 다르다(새 기준이 더 엄격하다).

**L1-충돌.** 다섯 항목 중 T-PR5·T-OR3·T-RF2는 둘 다 천장 근처거나 함께 올랐다. T-RD6(재독 금지)은 두 모델 모두 0.59로 동전 던지기이고, T-AW4(지연 실행)는 전체 기준 −0.07이지만 도달 기준 +0.11이다. 전체 기준이 떨어진 것은 base가 산출물을 안 써서 "실행할 스크립트가 없었던" run이 자동 통과로 잡혔기 때문이다. 결론은 "악화 신호 없음, 그러나 두 모델 다 불안정".

- step27의 compliance는 네 묶음 모두 0.75~0.81이고 층별로도 0.05 안쪽이다. 둘 다 실패한 196개에서도 L1 0.39 → 0.85, L2-먼 0.49 → 0.91. 학습이 가르친 것은 "풀 수 있을 때 절차를 지키기"가 아니라 "풀든 못 풀든 절차를 지키기"다.

## 7. 해석과 한계

**얻은 것.**

- 학습 workflow 세 개에서 배운 지시 따르기는 처음 보는 AI-DLC에서도 작동한다. L1(배운 것) +0.42, L2-중간 +0.38, L2-먼 +0.38. 학습에 없던 판정 형태(T-TR1b)도 도달 기준 +0.32다.
- 학습 습관에 반하는 지시(L1-충돌)에서 떨어지지 않았다. 과적합의 직접 신호는 없다.
- 이 개선은 문제 해결 여부, base의 사전 compliance, 완주 여부 어느 것으로 잘라도 같은 방향·비슷한 폭이다.

**못 얻은 것.**

- 문제 해결률은 그대로다. compliance 향상이 해결률로 이어지지 않았고, base가 이미 절차를 지키던 task에서는 해결률이 소폭 내려갔다(−0.02~−0.03, 통계적으로 구분은 안 됨).
- 행동 구간(수정 전 baseline, 같은 범위 재실행, 마지막 수정 후 테스트)과 명령 수준의 기록 사실성은 0.35~0.45에 머문다. 산출물의 형식을 채우는 법은 배웠지만, 산출물에 적은 것과 실제로 한 것을 일치시키는 습관은 절반만 배웠다. 기록한 명령·결과가 실제 실행과 다른 판정(T-RF1)이 step27에서도 해당 단계에 도달한 경우의 64%다.
- 뒷단계 문서를 미리 읽지 않기(T-RD3)는 base가 실패하던 경우의 25%만 고쳤다. 학습 workflow에서는 같은 조건이 순서 사슬 항목(`order`, invalidate=read_ahead)의 일부로만 채점되고 별도 항목은 아니었다(02 문서 G3). 단독 보상이 없었던 것이 원인일 수 있다.

**한계.**

- 모델 당 run이 task마다 하나씩이라 같은 task의 반복 분산은 모른다. 묶음 크기 44~46의 수치는 방향만 본다.
- L1-충돌 5개, L2-먼 6개는 항목 수가 적어 템플릿 하나(T-FM5가 L2-먼의 5/6)가 층 점수를 좌우한다. 층 점수보다 템플릿별 표를 봐야 한다.
- 새 기준(`aidlc_v4_ifeval`)은 평가 당시 실시간으로 돌지 않았고 저장된 산출물·diff로 재채점했다. 실행 순서·읽기 구간 판정은 대화 기록에서 복원하므로 실시간 채점과 같다. 산출물 내용 판정은 종료 시점 파일 기준이라 "중간에 썼다가 지운" 경우는 못 본다.
- compliance 0.78은 191개 must의 가중 평균이다. 같은 0.78이라도 어떤 항목을 지켰는지는 다르므로 비교는 템플릿 단위로 하는 것이 맞다.
