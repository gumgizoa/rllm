# 01. 템플릿 층 정의 (설계 문서 9.1절 1~2단계 결과)

> 기준 문서: `/mnt/nas1/mmi/ks.lim/docs/sdlc_if_template_design.md`
> 작성: 2026-10-22
> 입력: 학습 `agentos_v2`(AOS), `openspec_ff`(OSF), `speckit_bug`(SKB)의 `reward/rubric.yaml`, 그리고 AI-DLC 참고본 `aidlc_v4_gen/reward/rubric.yaml`(AID)
> 재현 스크립트: `scripts/inventory.py`(kind + 로직 인자 기준 원시 집계), `scripts/layer.py`(템플릿·기술 대응). 실행: `cd scripts && uv run --no-project --with pyyaml python layer.py`
> 원시 집계표: `template_inventory_raw.md` (템플릿 후보 키 152개)

## 1. 방법

1. **채점 대상만 셌다.** `unimplemented` 항목은 채점되지 않으므로 뺐다(AOS 50, OSF 107, SKB 30, AID 38).
2. **템플릿 후보 키를 만들었다.** 항목마다 키 = kind + 로직 선택 인자 + `window` 기준점 종류로 정했다.
   - 로직 선택 인자: `rule`, `mode`, `invalidate`, `relation`, `type`, `predicate`
   - `window` 기준점 종류: 첫 수정 이전 / 단계 안 / 마지막 수정 이후 / 산출물 쓰기 사이 / 전체
3. **같은 판정 로직의 키를 하나의 템플릿(T-*)으로 묶고, 템플릿을 기술(S1~S10)로 분류했다.**
   - workflow마다 이름만 다른 kind는 하나로 합쳤다(`<wf>.created_files`, `<wf>.read`, `<wf>.paths_written` 등).
4. **`window` 규칙을 다듬었다.** 설계 문서 2.3절보다 구체적으로 정했다.
   - **템플릿 축:** 구간의 경계가 제약 대상 행동과의 관계로 정의되는 경우. 예: "첫 소스 수정 이전", "마지막 수정 이후".
   - **인스턴스 인자:** 단순한 단계 구간("stage X 안")이나 전체 실행으로 범위만 바뀌는 경우. 대상 범위 변경과 같은 취급이다.

- 학습·평가 공통: 세 학습 workflow와 AID 모두에 있음

- 학습 X 고유: 한 학습 workflow에만 있음

## 3. 관찰

1. **항목의 60~70%가 S10(산출물 형식)이다.** 비율은 AOS 104/157(66%), OSF 86/141(61%), SKB 221/302(73%), AID 122/188(65%)이다. 대부분 T-FM2와 T-FM3, 즉 골격의 줄마다 생긴 항목이다. 보상의 대부분이 "형식을 갖췄는가"에서 나온다는 설계 문서 5.4절의 관찰이 수치로 확인된다.
2. **서로 다른 템플릿 수는 41개다.** 이 중 학습에 있는 것이 34개, AI-DLC에 있는 것이 28개다. 항목 수 788개(구현된 것, AID 포함)가 템플릿 41개로 묶인다.
3. **학습·평가 공통 템플릿이 핵심 행동을 거의 다 덮는다.** 문서 읽기, 순서, 수정 구간, 테스트 파일 금지, 기록 사실성, 형식이 여기에 속한다. 설계 문서 4.3절의 "대부분 인스턴스 분리" 결론과 같다.
4. **AI-DLC 고유 템플릿 후보 (구현된 것):** ※ 3단계에서 판정 로직과 학습 문서 노출을 확인한 결과, 아래 7개 중 순수 unseen(먼 변형)으로 남은 것은 T-FM5와 T-TR1의 키별 대응(T-TR1b)뿐이다. 나머지는 중간이나 가까운 변형으로 정정됐다(`02_train_eval_comparison.md` 3절). 모두 조건 없이 항상 발동한다. 그래서 과제 속성 계산 없이 L2로 쓸 수 있다(설계 문서 8절 6단계).

   | 템플릿 | 비고 |
   |---|---|
   | T-AW4 지연 실행 | SKB 습관과 **충돌** |
   | T-AW6 같은 범위 재실행 | T-AW3(사후 재실행)의 확장형인지 3단계에서 판정 |
   | T-RF2 "없음" 주장 반박 | T-RF1과의 거리 판정 필요 |
   | T-TR1 산출물 간 ID 커버리지 | 학습에 산출물-산출물 관계 항목이 없음 |
   | T-TR2 계획 이행 | SKB 문서와 거리 판정 필요 |
   | T-FM5 frontmatter 고정 | 학습에 frontmatter 항목이 없음 |
   | T-FM6 블록별 필드 | AOS `blocks`와 거리 판정 필요 |

5. **AI-DLC 고유지만 검증 함수가 없는 규칙 (AID `unimplemented`):** 이전 단계로 돌아가지 않음, 보이는 산출물 다시 읽지 않기, 질문 파일을 만들지 않음, 쓰기 전에 파일 존재 확인, 매 단계 후 중복 파일 확인 등. L2로 쓰려면 검증 함수가 새로 필요하다(9.1절 6단계).
   - 반대 방향 관계도 있다. "보이는 산출물 다시 읽지 않기"는 학습의 T-RD4(이전 산출물 읽기)와, "이전 단계로 돌아가지 않음"은 OSF의 "apply에서 ff로 돌아갈 수 있음"과 반대다.
6. **학습 workflow 고유 템플릿 (학습 다양성으로 유지할 후보):**
   - AOS: T-RD5, T-AW7, T-FM7
   - OSF: T-AW5, T-PG2, T-PR6
   - 둘 이상: T-OR2(OSF+SKB), T-PG1(AOS+OSF), T-SR1(AOS+OSF), T-WD4(AOS+SKB), T-PR4(OSF+SKB)
   - workflow별 형식: T-FM8

## 4. 한계

- **AI-DLC 쪽은 `aidlc_v4_gen` rubric을 참고본으로 썼다.** 이번 작업의 평가 기준인 `aidlc_v4` scorer는 이 템플릿 단위로 점수를 내지 않는다(설계 문서 4.4절). 대응표는 "AI-DLC 문서에 어떤 규칙이 있는가"의 근거로만 쓴다.
- **분류는 rubric 항목(이미 추출된 규칙)만 대상으로 했다.** workflow 문서 원문에서 rubric에 안 들어간 규칙은 `unimplemented`를 통해서만 일부 반영됐다. 단계 문서 원문을 전부 대조하는 작업은 3단계에서 필요한 부분만 한다.
- **판정 로직이 같은지는 `rule`, 인자, docstring 수준에서 판단했다.** "가까운 변형인지"와 "중간인지"의 판정은 3단계에서 검증 함수 코드와 반례 trajectory로 확인한다.
