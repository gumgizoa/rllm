## 3. 1차 eval 무효 사유

11-16 00:21에 띄운 speckit/openspec/agentos 세 eval은 agent_timeout 48~58%, 호출당 LLM 시간 32~36초로 정상(7~10초)의 3.5배. 처음 task부터 끝까지 균일하게 느렸고 agent.yaml·생성 길이는 변경 전과 같음. 변경 전 run의 세 eval도 같은 분에 동시 시작했으나 정상이었으므로 "동시 실행" 탓이 아니라 그 시각 서빙 측 조건(다른 GPU 작업 또는 vLLM 설정)임. episode 데이터로는 더 좁힐 수 없음.

## 4. assess 단계 파일 목록 vs golden patch vs 실제 편집

golden patch는 SWE-bench Verified(HF `princeton-nlp/SWE-bench_Verified`)의 `patch` 컬럼에서 `diff --git` 파일명을 뽑음. assessment.md는 `artifacts.workflow_outputs`에서, 실제 편집은 `artifacts.patch`(테스트 파일 제외)에서 봄. 경로는 `/testbed/` 접두와 `:줄번호`를 떼고 비교.
golden patch 파일 수: 1개 428, 2개 49, 3개 이상 22 task.

### 4.1 gold 파일 포함 여부 (assessment.md 있는 497/498 episode)

- 두 run 차이 없음.

- Suspected Code Paths는 넓게(gold 외 파일 포함 40%), Files likely to change는 좁게(정확 일치 70%) 적음.

### 4.2 Files likely to change 목록 vs 실제 편집한 소스 파일

| 관계 | 변경 전 | resolve | 새 run | resolve |
|---|---|---|---|---|
| 목록 그대로 편집 | 84% (396) | 58% | 84% (386) | 59% |
| 목록 전부 + 추가 파일 | 6% (27) | 44% | 5% (23) | 35% |
| 목록 일부만 편집 | 5% (22) | 23% | 5% (21) | 38% |
| 일부 겹침 + 추가 | 1% (5) | 80% | 1% (4) | 0% |
| 전혀 다른 파일 | 2% (11) | 36% | 4% (20) | 50% |
| 편집 없음 | 2% (8) | 0% | 1% (4) | 0% |

- 84%는 assessment에 적은 파일만 그대로 편집함. 계획에서 벗어나는 경우는 16%이고 resolve가 낮음(23~50%).
- 추가로 편집한 파일이 gold에 있던 경우는 32건 중 7건(변경 전), 27건 중 6건(새 run). 추가 편집은 대부분 gold 밖 파일이며, 이 경우 resolve 33~44%.
- 실제 편집이 gold를 전부 덮은 비율 77~78%, 그 resolve 65%. gold 파일을 하나도 안 건드린 12~13%의 resolve는 11~16%(동작은 같은데 다른 파일에서 고친 경우).

### 4.3 해석

assess 단계가 파일을 맞게 짚느냐가 결과를 거의 결정하고, 모델은 짚은 파일을 그대로 따름. 변경 전후 차이 없음. assess 품질을 reward에 넣을 거리로는 "Files likely to change가 gold 파일을 전부 포함" 같은 항목이 R과 독립적으로 측정 가능하지만, gold가 학습 데이터에 있어야 하고 eval 전용 지표로는 바로 쓸 수 있음.
